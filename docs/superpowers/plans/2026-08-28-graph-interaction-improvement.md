# 图谱交互改进方案

日期：2026-08-28
分支：`codex/graph-interaction`
状态：已完成

## 1. 背景与现状

当前 `/graph/` 使用 ECharts Canvas 绘制六类节点：论文、技术博客、目标、场景、任务和方法。
实现已经具备 d0/d1 初始分片、按相似度邻域加载、taxonomy/time 筛选、节点搜索和详情栏，但视觉编码与
首屏加载策略仍有以下问题：

- 论文和博客目前都是圆形彩色节点，和主题节点的层级差异不够明显；博客还使用了虚线描边。
- taxonomy 边和 similarity 边都以实线显示，taxonomy 边还会继承端点颜色，导致连线颜色不统一。
- 首屏只加载最新日报内容 d0 与 similarity 一跳邻居 d1。若 d0/d1 的内容节点少于配置上限，未继续向更远
  的相似内容扩展，画布会显得稀疏。

现有设计约束仍然有效：taxonomy 节点由 `taxonomy.json` 驱动，similarity 是唯一用于内容间距离的关系，
图谱只服务于导航、筛选和发现相邻内容；不引入后端、数据库或新的内容来源。

## 2. 目标与非目标

### 目标

1. 让论文/博客内容节点一眼区别于 taxonomy 主题节点，同时保留论文与博客的可辨识性。
2. 统一所有连线为灰色，并用实线/虚线表达关系类型：taxonomy 为实线，内容之间的 similarity 为虚线。
3. 所有节点取消描边；taxonomy 节点继续使用与页面 taxonomy 胶囊一致的颜色，内容节点改用灰色系。
4. 首屏在不超过 `graph_initial_content_nodes` 的前提下，沿 similarity 关系向外扩展，尽量填充可用内容节点。
5. 保持静态构建、分片加载、键盘可访问详情和现有图谱安全边界不变。

### 非目标

- 不改变论文/博客每日推荐数量、相似度模型、阈值、Top-K 或 canonical item schema。
- 不把 taxonomy 边用于“向外扩展”的距离计算；不把搜索命中写成新边。
- 不把全历史图一次性打包到首屏，也不增加全局节点上限之外的展示内容。
- 不引入 React、图数据库、运行时服务或新的图谱数据源。

## 3. 已确认视觉契约

### 3.1 节点

| 类型 | 形状/图标 | 颜色 | 描边 |
| --- | --- | --- | --- |
| 论文 | 小型文档图标 | 中性灰 | 无 |
| 技术博客 | 小型报纸/文章图标 | 与论文区分的另一档中性灰 | 无 |
| 目标 | 圆形 | `targets` 胶囊的 sky 色 | 无 |
| 场景 | 圆形 | `scenarios` 胶囊的 emerald 色 | 无 |
| 任务 | 圆形 | `tasks` 胶囊的 amber 色 | 无 |
| 方法 | 圆形 | `methods` 胶囊的 violet 色 | 无 |

内容节点仍使用 degree 的固定对数尺寸映射，但不显示画布标题；标题、类型和摘要继续由 tooltip、搜索结果
和详情栏提供。选中、搜索命中和一跳邻居状态只调整透明度/强调效果，不恢复描边，以满足“无描边节点”的
统一规则。

图标必须是构建可控的本地资源或内联静态资源，不从 CDN 加载，不包含用户文本，不改变现有静态部署方式。
图例也同步改为无描边的图标/色块示意。

### 3.2 连线

| 关系 | 线型 | 颜色 | 箭头 |
| --- | --- | --- | --- |
| taxonomy（内容 - 主题） | 实线 | 固定中性灰（拟沿用 `#94a3b8`） | 无 |
| similarity（论文/博客 - 论文/博客） | 虚线 | 同一固定中性灰 | 无 |

ECharts 适配层和图表 series 都使用固定灰色，不再使用 `color: "source"`、`color: "target"` 或主题节点
颜色继承。选中关系可以提高同一灰色的透明度，未选中关系降低透明度，但不得改变色相或线型。

## 4. 已确认首屏扩展策略

### 4.1 保留的边界

- `graph_initial_content_nodes` 继续作为首屏内容节点硬上限，并由 48 调整为 180。
- d0 仍是最新成功 digest 的内容节点，d1 仍保留为 d0 的 similarity 一跳节点，现有 manifest 与构建校验
  的 d0/d1 语义不变。
- taxonomy 节点只为最终已加载内容动态生成，不参与扩展排序或距离计算。

### 4.2 扩展算法（推荐方案）

在客户端加载 d0/d1 后，如果内容节点数仍小于上限，则复用已有 `adjacency_shards` 和 `node_shards` 做
确定性的 similarity BFS：

1. 将 d0 内容作为第一层种子；已加载的 d1 内容作为可继续展开的 frontier。
2. 按 frontier 的稳定顺序读取其 similarity 邻居；每个节点的邻居按 `score` 降序、邻居 ID 升序排列。
3. 依次加入尚未加载的内容节点，直到达到 `graph_initial_content_nodes` 或没有新的邻居。
4. 每加入一层，加载所需的 adjacency/node shard；已有 shard 由当前请求缓存复用，不重复下载。
5. 将已加载内容及其 taxonomy 边合并后再渲染；实际内容数始终 `<= graph_initial_content_nodes`。
6. 达到上限或没有新节点后，再读取最终 frontier 的邻接行，只补充两端都已加载的 similarity 边，保证末层
   诱导子图完整且不突破节点上限。

这样“往外扩展”只增加首屏已有数据契约允许的按需请求，不改变相似度 artifact，也不会为了填充数量引入
低质量或没有 similarity 关系的历史内容。若全量可达内容少于上限，则展示所有可达内容；无 d0 或无可达
similarity 邻居时保持现有空/小图行为。

### 4.3 稳定性与交互影响

- 扩展排序只依赖 similarity 分数和稳定 ID，不依赖请求完成先后或浏览器布局随机性。
- `?center=`、手动搜索、筛选和节点聚焦仍使用现有路径；首屏扩展完成后，用户继续聚焦可遍历其余历史内容。
- 加载状态需要明确显示“正在扩展首屏节点”，失败时保留已成功加载的 d0/d1 图，并在状态栏给出可理解的提示。
- 移动端仍关闭节点拖拽；扩展请求不改变页面滚动和详情栏布局。

## 6. 验收标准

- 论文与博客在画布上显示不同的小图标，均为灰色系；四类 taxonomy 节点颜色与页面胶囊一致。
- 所有节点没有可见描边；选中/搜索/邻居状态不引入彩色边框。
- taxonomy 边为灰色实线，similarity 边为灰色虚线，所有边无箭头。
- 首屏内容节点数不超过 `graph_initial_content_nodes=180`；当 d0/d1 不足上限且存在可达相似节点时，能继续向外
  扩展；可达节点不足时不填充无关内容。
- d0/d1 manifest、shard 校验、center/search/filter、详情链接和 Project Pages base path 回归通过。
- `pnpm test:build-contract`、`pnpm build` 和 `git diff --check` 通过，并完成桌面/移动端 `/graph/` 手动检查。

## 7. 确认结论

- 论文与技术博客采用两种不同图标，均为灰色圆形节点，图标线条使用黑灰色。
- 首屏只沿 similarity 边向外扩展，`graph_initial_content_nodes` 上限调整为 180。

## 8. 实施结果

- 节点、图例、边样式和首屏扩展均已按确认契约完成，图标作为站点本地 SVG 资源发布。
- 配置、Python/TypeScript Schema、构建校验、fixture 和测试均已同步到 180；历史 RunReport 继续兼容
  1--180 的既有快照，不改写历史数据。
- 首屏扩展按确定性 BFS 选择内容节点，并在最终 frontier 补齐已加载节点之间的 similarity 边。
